# 디자인 패스: "AI 티" 빼기 (D1~D3)

> 에이전트에게 주는 작업 지시서야. `docs/brief-wow.md`와 같이 쓴다. 순서는 맨 아래 7장을 봐.

## 0. 문제

사용자 피드백(2026-11-12): **"깔끔하긴 한데 디자인·색감·폰트가 AI 티가 너무 난다."**

대사가 AI 같았던 문제(`redesign.md` 2장)와 원인이 같아. **관점이 없는 안전한 기본값의 조합**이라서 그래. "더 세련되게"나 "더 예쁘게"로 고치면 다른 AI 기본값으로 바뀔 뿐이야. 이번엔 **정체성 하나를 정하고, 그걸로 모든 결정을 내려.**

## 1. 지금 코드에서 AI 티가 나는 곳 (진단)

`app/proto3d/rethink.css` 기준이야.

| 증상 | 어디 | 왜 AI 같나 |
| --- | --- | --- |
| 모든 패널이 유리(반투명 + `backdrop-filter: blur` + 흰 테두리 + 이중 그림자) | `.rt-weather`, `.rt-stat`, `.rt-dock`, `.rt-sheet`, `.rt-bubble`, `.rt-sound` | 요즘 생성 UI의 기본값이야. 패널마다 질감이 같아서 위계가 없어 |
| 모서리가 전부 9~22px로 둥긂, 태그는 알약 모양 | 거의 모든 클래스 | shadcn/Tailwind 기본 느낌. 모양에 의미가 없어 |
| 옅은 색 배경 + 같은 색 글자 태그(`#c4452f14`) | `.rt-tag.*`, `.rt-stamp` | 대시보드 템플릿의 상태 배지 그대로야 |
| 제목 위 작은 대문자 회색 라벨 | `.rt-kicker` | 생성 UI에서 가장 흔한 패턴이야 |
| 카드 안에 흰 카드, 1px 테두리 박스의 반복 | `.rt-note`, `.rt-cell`, `.rt-facts`, `.rt-then`, `.rt-pick-card` | 정보가 다 같은 상자에 담겨서 무엇이 중요한지 안 보여 |
| iOS식 세그먼트 탭 | `.rt-tabs`, `.rt-seg` | 기본 컴포넌트 그대로야 |
| 이니셜이 든 색 사각형 얼굴 | `.rt-face` | 아바타 자리표시자처럼 보여. 캐릭터가 있는데 안 써 |
| 아이콘 기본 세트(lucide-react) | `ui/*.tsx` 5곳 | 수많은 생성 앱과 똑같은 아이콘이야 |
| Pretendard 하나, 굵기 600/700 반복, 자간 -0.2 | `.proto3d` | 한국 핀테크 기본값이야. 숫자·제목·본문 구분이 굵기뿐이야 |
| 색: 짙은 초록 강조 + 초록 상승·빨강 하락 + 캐릭터 파랑·주황·보라 | 토큰 | 각각은 무난하지만 서로 관계가 없어. 3D 월드 색(`look.ts`)과도 따로 놀아 |
| **상승이 초록, 하락이 빨강** | `--rt-up`, `--rt-down` | **한국 관례(빨강 상승, 파랑 하락)와 반대야.** 초보자가 바로 헷갈려 |

## 2. 하지 말 것 (금지 목록)

- 패널 전체 유리 효과. 써야 한다면 딱 한 곳에만 이유를 갖고 써.
- 모든 요소에 같은 모서리 반경
- 옅은 색 알약 배지, 작은 대문자 키커, 카드 속 카드
- 보라·남색 그라디언트, 은은한 글로우, 의미 없는 그림자
- 기본 아이콘 세트를 손대지 않고 쓰기
- 이모지
- "깔끔하고 모던한" 같은 형용사로 방향 정하기

## 3. D1: 방향 시안 3개 (먼저, 작게)

**같은 화면 세 장을 세 방향으로** 만들어서 사용자에게 고르게 해. 전체 앱에 적용하지 마.
- 화면 ①: 리서치 노트 시트(신호 → 근거 → 판단 입력)
- 화면 ②: 판정 공개(도장 순간)
- 화면 ③: 첫 화면 위쪽 HUD와 아래 메뉴

시안은 `app/proto3d/look-lab/` 같은 별도 경로나 `?theme=a|b|c` 스위치로 만들어. 기존 화면은 깨지 않아야 해. 390×844 스크린샷을 3방향 × 3화면 = 9장 찍어.

**후보 방향** (더 나은 안이 있으면 하나를 바꿔도 돼)

| | 컨셉 | 글자 | 표면 | 이 서비스와 맞는 이유 |
| --- | --- | --- | --- | --- |
| **A. 현장 노트·표본실** | 식물학자의 관찰 노트, 표본 라벨, 채집 기록 | 제목은 명조나 세리프, 본문은 고딕, 숫자는 고정폭 | 종이 질감, 가는 괘선, 표본 태그, 도장과 손글씨 메모 | 정원, 관찰, 기록, 타임캡슐, 도장이 다 한 세계로 묶여 |
| **B. 리서치 리포트·경제지** | 증권사 리포트와 신문 경제면 | 단단한 고딕 제목, 큰 숫자, 각주 | 흰 종이, 굵은 구분선, 표, 강조색 하나 | "분석가 팀"이 진짜 리포트를 낸 느낌이야. 신뢰감 |
| **C. 정밀 계기·측량 도구** | 측량기, 계측기, 원예 도구 카탈로그 | 좁은 고딕, 눈금, 고정폭 숫자 | 짙은 바탕, 눈금자, 각진 모서리, 형광 포인트 하나 | 건조하고 날카로운 동료 톤과 맞고, 게임스러운 손맛도 있어 |

**방향마다 정할 것**
- **글자 2~3종**: 상업 이용 무료(OFL 등)여야 해. 한글은 서브셋으로 용량을 확인해.
- **색 토큰**
  - 3D 월드(`look.ts`의 하늘, 땅, 나무)에서 뽑아서 UI와 월드가 한 팔레트가 되게 해.
  - 상승 빨강, 하락 파랑은 한국 관례를 따라.
  - 캐릭터 색 셋은 Blender 모델 색과 맞춰.
- **표면 규칙**: 무엇은 종이, 무엇은 띠, 무엇은 떠 있는 것인지. 위계를 3단 이하로.
- **모양 규칙**: 모서리, 선 굵기, 간격 단위.
- **캐릭터 얼굴**: 이니셜 사각형 대신 3D 모델에서 렌더한 얼굴 컷을 써. `tools/blender/`에서 뽑아.
- **아이콘**: 직접 그린 SVG 세트로 하거나, 최소한 선 굵기·끝 모양을 방향에 맞게 손봐.

**D1 끝**: 9장을 나란히 붙인 비교 이미지와 방향별 3줄 설명을 주고 **멈춰서 사용자의 선택을 기다려.**

## 4. D2: 고른 방향을 전체에 적용

- 토큰을 한 곳에 모아: CSS 변수, 그리고 3D와 나누는 값은 `look.ts`.
- `rt-` 클래스 이름은 최대한 유지해서 e2e 셀렉터가 안 깨지게 해. 깨지면 테스트를 고쳐.
- 화면마다 1장 진단표의 증상이 남았는지 하나씩 지워.
- 3D 월드 쪽도 맞춰: 하늘, 땅, 그림자 색과 후처리(톤 매핑, 비네트, 그레인 등)가 UI와 같은 세계처럼 보이게 해.
- 세로 390×844, 가로 844×390, 데스크톱 1400px을 다 확인해.
- 명도 대비는 WCAG AA 이상이어야 해. 작은 글자도 읽혀야 해.

## 5. D3: 디테일 (여기서 사람 손맛이 나)

- **숫자**: 고정폭으로, 부호와 단위(%, 일)는 작게, 정렬은 소수점 기준으로 해.
- **간격**: 기준 단위 하나(예: 4px)로 맞추고, 덩어리 사이 간격과 덩어리 안 간격을 확실히 다르게 해.
- **글줄**: 한국어 줄바꿈(`word-break: keep-all`)과 행간을 정리하고, 제목 한 줄 끝에 한 글자만 남는 걸 막아.
- **눌림·전환**: 모든 버튼에 그 방향다운 눌림 반응을 줘. 예: A는 종이가 눌리는 그림자, C는 딸깍 눈금.
- **의도된 불완전함 한 가지**: 손글씨 메모, 살짝 비뚤어진 도장, 종이 결 같은 것. 딱 하나만, 방향에 맞게.

## 6. 자가 검사

- **이름 가리기 테스트**: 로고를 가린 스크린샷이 다른 핀테크 앱이나 AI 데모와 구분되나?
- **이유 테스트**: 색, 모양, 글자 하나하나에 "이 방향이라서"라는 이유를 댈 수 있나? 못 대면 기본값이야.
- **월드 테스트**: UI만 떼어 봐도 정원 게임의 UI로 보이나?
- 기존 테스트: `tsc --noEmit`, `test:unit`, `proto3d` e2e, `build`가 통과해야 해.
