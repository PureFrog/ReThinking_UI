# ReThinking_UI 협업 지침서

**버전** 3.0 · 2026-10-28 (로컬 협업 방식)
**참여자**: 사용자(PureFrog), 팀원, Claude(코드), ChatGPT(이미지 제작), Codex(팀원의 코딩 도구 또는 작동 테스트)
**저장소**: https://github.com/PureFrog/ReThinking_UI

이 문서는 **누가, 어디서, 어떤 순서로 일하고, 결과를 어디에 남기는지**를 정한다. 무엇을 만들지는 `docs/ux-spec.md`가 정한다.

---

## 0. 한눈에 보기

- **작업은 사용자 컴퓨터의 로컬 폴더 하나에서 한다.** 개발 서버를 띄워두고, 고치면 바로 화면에서 확인한다.
- **AI끼리는 직접 대화하지 않는다.** 폴더 안의 `collab/`을 우편함으로 쓴다. Claude가 요청서를 쓰고, 사용자가 GPT에게 전달하고, GPT의 결과물은 정해진 칸으로 들어온다.
- **깃헙은 백업과 공유용이다.** 사용자가 OK한 상태만 푸시한다. 브랜치·PR·Preview 배포 절차는 쓰지 않는다.
- **판단이 부딪히면** 사용자 결정 > `CLAUDE.md`·`AGENTS.md` 절대 규칙 > `docs/ux-spec.md` > 이 문서 > `docs/archive/handoff.md` 순으로 이긴다. 화면을 보고 느낀 사용자의 감각이 최종 판정이다.

## 1. 프로젝트 맥락 — 모든 에이전트가 알아야 할 것

**무엇인가.** '마음이 자라는 정원'. 사용자가 캐릭터로 아이소메트릭 집과 정원을 돌아다니며, 주식 보유를 표현한 나무를 돌보고, 놀러 오는 동물 친구(모아·토리·루온)와 유대를 쌓고, 집을 꾸미는 React + Phaser 웹 UI다. 투자 일지·퀴즈·회고 같은 성찰 행동이 정원 성장의 연료다.

**왜 만드는가.** FDS A조 팀 프로젝트 '다시 생각해볼래?'의 사용자 경험 부분이다. 서비스의 목적은 손실 중인 종목의 보유 이유를 투자자가 **스스로** 다시 생각하게 돕는 것이다. 캐릭터는 매매를 권하지 않고 질문한다. 금융 분석 모델은 팀이 따로 개발 중이고, 이 UI에서는 **모의 데이터와 준비된 대사**로 그 결과가 들어갈 자리를 만든다.

**마감.** 팀 프로젝트는 **2026-11-27**에 끝난다. 절차보다 사용자가 체감하는 화면 품질에 시간을 쓴다.

**지금까지의 경과.** GPT가 ChatGPT Sites 환경에서 프로토타입을 만들었다(`docs/archive/handoff.md`). 사용자는 결과를 "감이 없다"고 판단했다. 설계서를 줘도 디자인이 거의 안 바뀌었고, 말풍선을 누를 때마다 안내 토스트가 반복됐고, 캐릭터가 살아 있지 않았고, 서랍·책장 패널이 별로였고, 아이템을 그림 없이 보여줬고, 일지·퀴즈 성취감 시스템이 빠져 있었다. 그래서 코드는 Claude, 이미지와 작동 테스트는 GPT로 역할을 나눴다.

**사용자.** 금융·데이터 분석 배경의 학생이다. 개발 전문가가 아니므로, 사용자에게 시키는 일은 최소로 하고 명령어와 클릭 경로를 정확히 알려준다. 사용자와는 한국어로, 짧고 직설적으로 말한다.

## 2. 역할과 구역

| | 하는 일 | 하지 않는 일 | 쓸 수 있는 곳 |
| --- | --- | --- | --- |
| **사용자** | 방향 결정, 화면 확인과 감각 피드백, 에셋 승인, GPT에게 요청 전달, 커밋·푸시 승인 | — | 전부 |
| **Claude** | 모든 코드, 명세 문서, 요청서 작성, 에셋 통합, 테스트 시나리오(Playwright) 작성, 1차 화면 확인, 커밋 | 이미지 생성, 사용자 OK 없는 푸시 | `collab/from-gpt/`, `public/assets/incoming/`을 **제외한** 전부 |
| **팀원 (+ Codex 같은 AI 도구)** | 맡은 기능의 코드·테스트·문서, 작업 기록 | 설계서 [결정] 혼자 바꾸기, 배포 설정 수정, 그림을 코드로 고치기 | `collab/from-gpt/`, `public/assets/incoming/`을 **제외한** 전부. 규칙은 `AGENTS.md` |
| **ChatGPT — 이미지** | 요청서를 보고 이미지 제작, 규격 자체 점검 | 코드·문서 수정, 승인 단계 건너뛰기 | 결과물을 사용자에게 전달 (사용자가 `public/assets/incoming/`에 넣음) |
| **Codex — 작동 테스트만 맡았을 때** | 로컬에서 개발 서버와 테스트 실행, 시나리오 밖 탐색, 보고서 작성 | 코드·문서·테스트 파일 수정, 디자인 결정 | `collab/from-gpt/`, `test-results/`(커밋 안 함) |

**구역을 넘지 않는다.** 테스트만 맡은 Codex는 버그를 찾아도 고치지 않는다. 보고서에 적고, 고치는 건 코드를 맡은 쪽(Claude 또는 팀원)이 한다. 저장소는 동시에 여럿이 고치지 않고 **한 사람에게 맡기는 방식**으로 넘긴다(8장).

**ChatGPT 테스트의 범위.** 보고할 것은 "명세와 다르다", "동작이 깨졌다", "금지 목록 위반이다" 세 가지다. 디자인 의견은 보고서의 "제안" 칸에만 쓰고, Claude는 사용자 확인 없이 반영하지 않는다.

**GPT의 어느 도구가 무엇을 할 수 있나.** ChatGPT 일반 채팅과 클라우드 브라우저 기능은 사용자 컴퓨터의 localhost를 열 수 없다. 작동 테스트는 **사용자 컴퓨터에서 실행하는 Codex**로만 한다. 이미지는 ChatGPT 채팅에서 만든다.

## 3. 폴더 구조와 우편함

전체 폴더 구조는 `README.md`에 있다. 협업에 쓰는 곳만 보면:

```
collab/
├── log.md                 작업 기록. 누가 언제 무엇을 했는지 한 줄씩
├── templates/             요청서·보고서 양식
├── to-gpt/                GPT 요청서 (첨부 그림 폴더 NNN-refs/는 git에 없음)
├── to-nanobanana/         나노바나나 요청서 (첨부 그림 폴더는 git에 없음)
└── from-gpt/              GPT → 결과 보고서·메모
public/assets/incoming/    GPT가 만든 그림이 처음 들어오는 곳 (git에 없음)
public/assets/<폴더>/       검수·정리한 그림 (게임이 쓰는 곳)
scripts/gpt-handoff.sh     요청서를 클립보드에, 첨부를 Finder에 여는 도구
scripts/art/               시트 자르기·나무 자리 재기 같은 기계적 손질 도구
```

**요청서 번호.** `to-gpt/`와 `from-gpt/`는 같은 세 자리 번호를 공유한다. 요청 `007-style-sample.md`의 답장은 `007-style-sample-report.md`다. 번호는 `log.md`의 마지막 번호 + 1.

**log.md 한 줄 형식**

```
2026-10-29 14:20 | Claude | 007 요청서 작성 — 스타일 시안 1장
2026-10-29 15:05 | 사용자 | 007 GPT에 전달
2026-10-29 16:40 | 사용자 | 007 그림 incoming/에 넣음
2026-10-29 16:55 | Claude | 007 게임에 붙여 스크린샷 → 사용자 승인 대기
```

## 5. 한 단계의 사이클

작업 단위는 `ux-spec.md` 13.4의 **단계**다. 한 번에 한 단계만 하고, **한 번에 한 AI만 폴더에서 작업한다.**

1. **계획** — Claude가 이번 단계에서 바꿀 것을 3~5줄로 말한다. 사용자가 OK하면 시작.
2. **구현** — Claude가 코드를 고친다. 개발 서버가 떠 있으니 사용자는 바로 화면에서 본다. 그림이 없으면 임시 그림으로 진행하고 요청서를 쓴다(6장).
3. **테스트 시나리오** — Claude가 이번 단계의 핵심 동작을 `tests/e2e/`에 Playwright 테스트로 추가한다. 예: "친구 말풍선 클릭 → 안내 토스트 없음", "서랍 → 아이템이 그림 칸으로 보임".
4. **자동 검사** — 타입 검사, 모델 테스트, e2e 테스트, 빌드.
5. **1차 확인 (Claude)** — 세로 휴대폰 390×844(기본), 가로 844×390, 데스크톱 1400px 화면을 직접 열어 스크린샷을 남긴다. 못 했으면 못 했다고 말한다.
6. **사용자 확인** — 사용자가 직접 만져본다. 감각 피드백은 Claude가 그 자리에서 고친다. 2~6을 반복한다.
7. **커밋** — 사용자가 커밋하라고 하면 Claude가 `[stage-n] 요약` 메시지로 커밋한다. 그 전에는 커밋하지 않는다.
8. **작동 테스트 (Codex, 선택)** — 사용자가 원하면 Claude가 테스트 요청서를 쓰고, 사용자가 Codex에게 넘긴다(7장). 보고서에 문제가 있으면 Claude가 고치고 5로 돌아간다.
9. **푸시** — 사용자 OK가 나면 Claude가 `main`으로 푸시한다. 다음 단계로 넘어간다.

**넘기기 규칙.** AI에게 폴더를 넘기기 전에 커밋되지 않은 변경이 없게 한다. 커밋이 찍혀 있으면 무엇이 잘못돼도 그 지점으로 돌아갈 수 있다. Claude가 작업 중일 때 Codex를 돌리지 않는다.

**막혔을 때.** 같은 방법을 세 번 넘게 반복하지 않는다. 무엇이 막혔는지와 선택지를 사용자에게 바로 말한다.

## 6. 이미지 협업

### 6.1 요청 (Claude)

`collab/templates/asset-request.md` 양식으로 `collab/to-gpt/NNN-<이름>.md`를 쓴다. 규격의 근거는 `ux-spec.md` 6장이다. GPT가 저장소를 읽지 못해도 요청서 하나만으로 작업할 수 있게, 필요한 스타일 규칙을 요청서 안에 다 쓴다.

### 6.2 전달 (사용자)

요청서 파일을 ChatGPT에 첨부하거나 내용을 붙여넣는다. 참고 이미지가 적혀 있으면 그 파일도 같이 첨부한다.

### 6.3 납품 (ChatGPT → 사용자) — 사용자가 할 일은 두 가지뿐

1. 받은 그림을 **파일 이름 신경 쓰지 말고** `public/assets/incoming/NNN/`에 넣는다 (NNN = 요청서 번호, 예: `incoming/002/`).
2. Claude에게 "NNN 들어왔어"라고 말하고, GPT가 채팅으로 해준 설명이 있으면 그대로 붙여넣는다.

자르기, 이름 바꾸기, 폴더 정리, 설명 기록(`collab/log.md`)은 전부 Claude가 한다. 그림을 채팅에 따로 올릴 필요는 없다 — Claude가 폴더에서 바로 연다.
(2026-10-30 사용자 결정: 파일명 통일·report 파일 저장 같은 손작업을 사용자에게 시키지 않는다.)

### 6.4 통합 (Claude)

규격(크기, 앵커, 투명 배경)을 확인하고, `scripts/art/cut-sheet.py`로 칸을 잘라 `public/assets/<폴더>/`에 정해진 이름으로 저장해 게임에 붙인다. `incoming/` 원본은 건드리지 않는다. 게임 화면 스크린샷을 사용자에게 보여준다. 규격이 틀렸으면 무엇이 틀렸는지 적은 재요청서를 같은 번호의 `-v2`로 쓴다.

### 6.5 승인 관문 — 건너뛰지 않는다

1. 스타일 시안 1장 → 사용자 승인
2. 캐릭터별 레퍼런스 시트 → 사용자 승인
3. 애니메이션 프레임과 나머지 에셋 → 게임에 넣은 화면으로 사용자 승인

승인은 **사용자만** 한다. 단독 이미지가 아니라 **게임 화면 안에서** 보고 승인한다.

### 6.6 이미지 규칙

- 실제 기업의 로고·상표·제품 이미지를 그리지 않는다. 종목과 연결된 아이템은 업종을 상징하는 일반 사물로 표현한다.
- 같은 캐릭터의 모든 프레임은 승인된 레퍼런스 시트를 참조로 넣어 만든다.
- 사용한 생성 도구와 약관 확인 결과를 `public/assets/LICENSE_NOTES.md`에 적는다(Claude가 사용자에게 확인해 기록).

## 7. 작동 테스트 협업 (Codex)

### 7.1 요청 (Claude)

`collab/templates/test-request.md` 양식으로 `collab/to-gpt/NNN-test-stage-n.md`를 쓴다. 요청서에는 다음이 들어간다.

- 테스트할 커밋
- 실행 명령 (개발 서버, e2e 테스트)
- 시나리오 목록과 각 시나리오의 기대 결과, 근거가 된 `ux-spec.md` 절
- 이번 단계와 상관없이 매번 보는 것: `ux-spec.md` 11.16 금지 목록 전부
- 화면 크기: 세로 휴대폰 390×844(기본), 가로 844×390, 데스크톱 1400px

### 7.2 실행 (사용자 → Codex)

사용자는 이 폴더에서 Codex를 실행하고, 11.4의 문장과 요청서 경로를 준다.

### 7.3 보고 (Codex)

`collab/templates/test-report.md` 양식으로 `collab/from-gpt/NNN-test-stage-n-report.md`를 쓴다. 스크린샷은 `test-results/NNN/`에 저장하고 보고서에서 경로로 가리킨다.

- **실제로 실행하고 본 것만 쓴다.** 못 한 것은 Not Tested와 이유를 쓴다.
- 검수한 커밋 SHA를 반드시 적는다. 새 커밋이 생기면 이전 보고서는 무효다.
- 명세와 다른 점과 개인 의견을 섞지 않는다. 의견은 "제안" 칸에만.
- 코드, 테스트 파일, 문서를 고치지 않는다.

**심각도**: Critical = 진행 불가·데이터 손실 / High = 명세·금지 목록 위반, 핵심 흐름 오류 / Medium = 일부 상황에서만 나는 오류 / Low = 사소한 시각 결함.

### 7.4 반영 (Claude)

보고서를 읽고, 재현하고, 고친다. 고친 항목을 `log.md`에 적고, 필요하면 같은 번호의 재테스트 요청서(`-v2`)를 쓴다. "제안" 칸은 사용자에게 보여주고 결정을 받는다.

## 8. 깃헙 사용 규칙

- 커밋은 사용자가 하라고 할 때만 한다.
- **깃헙 푸시는 사용자가 OK한 상태만.** 한 단계가 끝날 때 한 번 푸시하는 게 기본이다.
- 커밋 메시지: `[stage-n] 요약`, `[asset NNN] 요약`, `[fix] 요약`, `[docs] 요약`.
- 커밋하지 않는 것: `node_modules/`, 빌드 결과물, `test-results/`, `.env*`, 토큰.
- **맡기는 방식.** 한 번에 한 사람(또는 한 AI)만 작업한다. 브랜치는 따로 쓰지 않고 `main` 하나를 쓴다.
  - 넘기는 사람: 작업을 커밋하고 푸시한 뒤 `collab/log.md`에 어디까지 했는지 한 줄 남긴다.
  - 받는 사람: `git pull`로 최신을 받고, `docs/features.md`(만든 기능·남은 일 한눈에), `collab/log.md`, `docs/deferred.md`를 읽고 시작한다.

### 11.2 ChatGPT — 코드를 깃헙으로 옮기기 (처음 한 번)

```text
/workspace/sites/character-garden의 소스를 기존 git 기록을 유지한 채
https://github.com/PureFrog/ReThinking_UI 의 main 브랜치로 푸시해줘.
node_modules, 빌드 결과물, .env 같은 비밀 파일과 토큰은 빼고,
public/assets와 tests는 포함해. 원본 기획 docx는 docs/ 폴더에 넣어줘.
저장소에 setup-docs라는 브랜치가 이미 있는데 그건 건드리지 마.
코드 내용은 바꾸지 마. 푸시가 안 되면 같은 조건으로 zip을 만들어 나한테 줘.
```

```text
첨부한 요청서대로 이미지를 만들어줘.
요청서의 파일명, 캔버스 크기, 앵커 위치, 투명 배경을 정확히 지켜.

```
