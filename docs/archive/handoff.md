마음이 자라는 정원 — 다른 AI를 위한 프로젝트 인수인계 설명서
작성 기준: 2026-10-27 / 최신 배포 소스 기준

1. 이 프로젝트를 한 문장으로 설명하면
사용자가 자신의 캐릭터로 아이소메트릭 집과 정원을 돌아다니며, 주식 보유를 표현한 나무를 돌보고, 가끔 찾아오는 동물 친구들과 대화하고, 선물을 받거나 집을 꾸미는 UI 프로토타입이다.

핵심은 금융 대시보드가 아니라 ‘내 캐릭터가 살아가는 집과 정원’이다. 거의 모든 기능을 집과 마당의 실제 사물에 연결한다. 현재는 React + Phaser 기반의 브라우저 체험판이며 금융 데이터·공시·대화·투자 사건은 모두 모의 데이터와 준비된 응답이다. 실제 백엔드, 실시간 시세, 공시 API, LLM API, 주문·거래 시스템은 연결하지 않았다.

2. 다음 AI가 가장 먼저 알아야 할 사용자 의도
- 참고 이미지처럼 비스듬히 내려다보는 귀엽고 아기자기한 아이소메트릭 2.5D 공간을 원한다.
- 정적인 그림을 클릭하는 체험보다, 플레이어가 직접 돌아다니고 사물에 다가가 상호작용하는 느낌이 중요하다.
- 화면 바깥에 기능 버튼과 패널을 잔뜩 늘어놓는 방식은 사용자가 원하지 않는다.
- 캐릭터 대사는 머리 위 말풍선, 선택지는 캐릭터 몸 옆의 약간 투명한 메뉴에 표시한다. 일반 대화를 중앙 팝업으로 바꾸지 않는다.
- 플레이어 캐릭터는 집 안에 실제로 존재하며 마우스로 바닥을 클릭해 이동한다.
- 동물 캐릭터는 상주 주민이 아니라 가끔 놀러 오는 방문객이다. 방문 중 가만히 서 있지 않고 먼저 말 걸기, 산책, 나무 물주기를 한다.
- 집과 마당은 넓어야 한다. 최근 확장했고 외곽 울타리는 제거했다.
- 아이템·치장품·가구는 실제 사용·착용·배치가 되어야 한다.
- 현재 UI 프로토타입이라는 범위를 유지한다. 사용자의 별도 요청 없이 실제 금융/채팅 백엔드를 붙이지 않는다.

3. 사용자 요구사항이 반영된 현재 조작법

바닥: 클릭한 칸으로 플레이어가 걸어간다. 가구와 나무 등 막힌 칸을 돌아가는 경로 탐색을 사용한다.
서랍: 수집한 선물 보유함, 옷장, 집 꾸미기, 사용법을 연다.
책장: 준비된 투자 퀴즈를 연다.
테이블 위 기록장: 보유 종목, 모의 수익률/보유일/손실 지속일 설정, 성장 기준, 대화 기록과 판단을 본다.
소파: 쉬는 연출용 안내 문구가 나온다.
우편함: 방문객을 초대한다. 이미 방문한 친구가 있으면 다음 초대는 기다린다.
바닥 선물상자: 플레이어가 가까이 가 주운 후 선물 내용과 보낸 사람을 보여준다. 익명 선물은 보유함에서도 익명이다.
씨앗박스: 6개 밭 중 빈 밭을 고르고 가상 종목·매수일·단가·수량을 입력한다. 플레이어가 밭으로 걸어가 심는다.
삽: 정리할 나무를 고르고 확인한 후 플레이어가 다가가 제거한다. 해당 모의 보유 기록도 함께 삭제된다.
나무: 클릭하면 가지가 흔들리고 나무 옆에 ‘물주기’와 ‘정보 보기’가 나온다. 심기·제거·모의 수치 편집은 이 메뉴에 넣지 않는다.
물주기: 플레이어가 다가간 후 물뿌리개 기울임과 물방울 애니메이션을 실행한다. 물주기로 수익률을 올리지는 않는다.
나무 정보: 읽기 전용 보유 정보다. 모의 수치를 바꾸려면 집 안 기록장을 이용한다.
배치된 가구: 클릭 후 다른 자리로 옮기거나 서랍에 보관한다.
Esc: 열린 대화/패널 또는 가구 배치를 취소한다.

사물 기능에는 읽기 편한 중앙 패널도 사용한다. ‘거의 모든 UI를 집 안 상호작용에 넣는다’는 요구는 모든 패널을 금지하는 뜻이 아니라, 기능을 사물을 통해 열고 조작한다는 의미로 구현했다. 특히 NPC 대화는 반드시 월드 안 말풍선과 옆 선택지를 유지한다.

4. 등장 캐릭터

플레이어: 사람이 직접 조작하는 작은 인간형 캐릭터. 현재 절차적 도형으로 그리며 모자, 얼굴, 몸, 걷는 다리가 있다.
모아: 크림색 토끼. 다정하고 사용자를 재촉하지 않는 편지 친구. 선물은 ‘위로 사탕’.
토리: 주황색 다람쥐. 씩씩하고 활기차며 사투리 말투를 쓴다. 선물은 ‘여름 선글라스’.
루온: 짙은 회색 고양이. 무심한 듯 조용히 챙겨준다. 자신이 선물했다는 사실을 숨기는 성격이며 ‘작은 별 조명’을 익명으로 준다.
초기 바닥 선물에는 익명의 ‘포근한 담요’가 있다.

5. 방문객과 대화

방문객은 한 번에 한 명만 등장한다. 처음에는 없고, 데모에서는 약 18초 후 첫 친구가 온다. 우편함으로 직접 초대할 수도 있다.
최신 구현은 도착 인사 → 나무에 다가가 물주기 → 집/마당 산책 → 플레이어 근처로 다가와 먼저 말 걸기를 반복한다. 세부 이동 지점과 나무는 일부 무작위로 고른다. 행동 사이에는 대략 6.5~10초 정도의 대기 시간이 있다.
먼저 건네는 말은 별도의 ambient 말풍선으로 표시하고 약 7.5초 후 닫는다. 친구를 클릭하면 정식 대화 선택지를 연다. 대화/패널/배치 중에는 다음 자율 행동을 미룬다. 이미 걷는 중이던 이동은 완료될 수 있다.
도착 후 약 110초에 귀가를 시도하며 대화·패널·물주기 중이면 지연한다. 돌아간 뒤 약 65~90초에 다음 방문을 예약한다. 이 시간들은 제품 확정값이 아니라 시연용이다.

대화는 준비된 문구다. ‘나무 이야기’를 선택하면 가상 계약 종료 사건, 반대 근거, 사용자 보유 이유 입력, 유지/수정/유보 판단 기록을 체험한다. 입력 키워드에 따라 준비된 응답을 고르는 구조이며 실제 LLM 추론이 아니다.

모든 NPC 대사에는 타이핑 효과를 적용했다.
- 처음 약 180ms 후 시작, 기본 글자 간격 약 38ms.
- 쉼표 뒤 약 140ms, 마침표·물음표·느낌표·말줄임표 뒤 약 260ms 쉰다.
- 출력 중 말풍선을 누르면 전체 문장이 즉시 표시된다.
- 캐릭터 위치 추적 때문에 대사가 재시작되지 않게 캐릭터 ID와 대사로 컴포넌트 키를 구성했다.
- 닫힘/문장 교체 시 타이머를 정리한다.

6. 나무 형태 규칙 — 중요

단순히 수익이면 밝고 손실이면 어두운 정도가 아니라 크기·잎·줄기·열매가 달라져야 한다.
- 수익률 +10% 이상: 열매가 빛나는 발광/반짝임.
- 보유 기간이 기본 180일 이상이고 수익률이 양수: 큰 고목과 넓은 뿌리.
- 수익률 -10% 미만: 작고 처진 나무, 낙엽.
- 수익률 -20% 이하인 상태가 기본 60일 이상 지속: 잎이 없고 줄기/가지가 꺾여 거의 쓰러진 모습.
- 정확히 -10%는 축소 조건이 아니며, 정확히 +10%는 발광 조건이다.
- 고목과 발광은 동시에 적용될 수 있다.
- 오래 보유한 기간과 심한 손실이 지속된 기간은 별도 수치다.
- 손익 회복 시 형태도 회복한다.
- 180일/60일 기준은 기록장에서 바꿀 수 있는 프로토타입 기본값이다.
- 현재 보유일 계산 기준일은 고정된 2026-10-27이다. 실제 오늘 날짜로 자동 갱신되지 않는다.
- 나무 상태는 보유 손익의 시각화이며 기업 위험 판정/매매 추천이 아니다.

초기 가상 종목 4개는 각각 발광, 고목, 축소, 잎 없는 손상 상태를 보여준다. 밭은 총 6개다.

7. 아이템·옷장·집 꾸미기

서랍의 옷장에서 ‘산책 목도리’, ‘꽃 장식’을 즉시 착용/해제할 수 있다. 받은 ‘여름 선글라스’도 착용 가능하다. 현재 장식은 한 번에 하나만 착용하며 플레이어 도형 위에 실제 그래픽을 그린다.
작은 별 조명과 포근한 담요는 배치할 수 있다. 위로 사탕은 한 번 사용하는 소모품이다.
기본 가구 목록에는 화분, 티 테이블, 러그가 있다. 현재 기본 가구는 수량 제한 없는 시연용이다.
가구는 서랍에서 꺼내기 → 반투명 배치 미리보기 → 빈 바닥 클릭 → 플레이어 이동 → 도착 시 배치 순서다. 실내와 마당 모두 가능하다.
빈 칸, 플레이어/방문객 위치, 주요 사물 접근 가능 여부를 검사한다. 배치 취소 후 도착 콜백이 가구를 뒤늦게 놓지 않도록 ActionGate 토큰을 사용한다. 러그는 캐릭터 아래에 그리며 통과 가능하다.

8. 화면·기술 구조

React 19.2.6, TypeScript 5.9.3, Phaser 3.90.0. Sites Vinext 기반이며 기존 Worker 배포 구성을 유지한다.
Phaser 캔버스는 1400×1050, 공간은 17×15칸, 집은 약 9×8칸이다. 이전 13×11 전체 공간/6×6 집에서 확장했다. 외곽 울타리를 그리는 호출은 제거했다. fence() 헬퍼는 사용하지 않는 코드로 남아 있다.
아이소메트릭 투영은 x=700+(gridX-gridY)*43, y=235+(gridX+gridY)*21.5 이다. 실내 위치에는 높이 보정을 적용한다. 실제 3D 메시가 아니라 2D 스프라이트/도형을 투영하고 발 위치 y로 깊이를 정렬하는 2.5D다.
이동은 4방향 BFS와 칸 단위 Tween이다. 사물 상호작용은 목적 칸의 인접 칸까지 접근한다. 장면 이벤트 브리지를 통해 React 상태/패널과 Phaser 월드를 연결한다.

핵심 파일:
- app/page.tsx: React 상태, 사물 패널, NPC 대화/선택지, ambient 말풍선, 보유함/옷장/배치 UI, localStorage, 이벤트 연결.
- app/game.ts: GardenScene, 투영, 집/정원/가구 도형, 플레이어/방문객 이동, 자율 행동, 물주기, 선물, 나무 렌더링, 배치와 충돌.
- app/model.ts: Holding/Rules/Decoration/GiftBox 타입, 모의 데이터, treeState, heldDays, route, ActionGate, dialogueLayout, giftPosition, 한국어 조사 helper.
- app/TypedDialogue.tsx: 타이핑 출력, 건너뛰기, 타이머 정리, 완료 문장 접근성 안내.
- app/globals.css: 전체 화면 월드, 말풍선/반투명 선택지, 사물 패널, 반응형 스타일.
- public/assets/garden-atlas.png: 생성 이미지 기반 투명 아틀라스. 1536×1024, 512×512 프레임 3열×2행. 위 3개 캐릭터, 아래 3개 나무.
- tests/model.test.mjs: TypeScript 모델을 변환해 node:test로 실행하는 14개 테스트.

주요 장면 메서드: visit / guestActivity / guestSays / scheduleActivity / scheduleDeparture / depart / walk / interact / selectTree / wateringAnimation / placeAt / cancelPlace / drawTrees / dress.
주요 이벤트: sync, ready, hint, walking, visitor, character, ambient, anchor, close-talk, tree-menu, close-tree, water, plant-seed, planted, uproot, removed, arrival-gift, pickup, place, placed, cancel-place, placement-cancelled, decor-select, invite, leave, lock, talk-state.

9. 저장 데이터와 제한

브라우저 localStorage 키: little-garden-v2.
저장: holdings, rules, decor, gifts, claimed, equipped, used, records, decision.
초기화되는 임시 상태: 플레이어 위치, 방문객, 진행 중 동작, 열린 패널/대화.
다른 기기/브라우저와 동기화하지 않으며 서버 DB를 사용하지 않는다.
Gift ID가 visit-캐릭터번호 형태이므로 같은 친구의 방문 선물은 현재 데모에서 중복 생성되지 않는다. 매 방문 새 선물이 생기는 완전한 보상 시스템은 아니다.

10. 검증 상태와 다음에 먼저 점검할 사항

최근 소스는 타입 검사, 프레임워크 빌드, 기존 모델 테스트 14개를 통과했다. 테스트는 나무 임계값/회복, 이동 경로, 배치 취소, 말풍선 가로 경계, 선물 위치, 넓어진 마당 경계를 검증한다. 방문객 자율 행동 전체를 자동 테스트로 검증한 것은 아니다.
이전 버전에서는 브라우저에서 씨앗 심기, 삽 제거, 물주기, 목도리 착용, 서랍, 배치 취소 등을 직접 확인했다.
최신 ‘방문객 자율 행동 + 울타리 제거’ 버전과 타이핑 효과는 코드/빌드 검증 후 배포했으나 최신 화면의 직접 클릭 검증은 완료하지 못했다. 브라우저 실행의 자동 승인 검토가 워크스페이스 크레딧 부족을 이유로 거절했기 때문이다. 배포 성공과 브라우저 시각 검증 완료를 혼동하지 말 것.

다음 AI가 우선 점검할 내용:
1) 방문 → 인사 → 물주기 → 산책 → 플레이어 접근 → 귀가가 한 사이클 정상 동작하는지.
2) 걷는 친구를 눌러 대화할 때, 대화 접근 중/종료 후 행동이 멈추거나 중복되지 않는지.
3) 대화·배치·패널·물주기·귀가 타이머가 겹칠 때 상태가 꼬이지 않는지.
